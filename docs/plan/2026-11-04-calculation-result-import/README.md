# 计算结果导入与结构配准

状态：未开始。需求与验证：新增计算产物导入和结构关联需求，复用 R-006、R-007、R-014、R-029，沿用 T-DOM-01、T-DOM-06、T-FMT-03、T-FMT-04、T-DEMO-01，新增导出映射与结果配准用例。

## 需求与当前事实

计算在 Alchemion 外完成。用户通过工作台选择本地文件，SDK 消费者提供文件内容或已解析的结果。当前格式入口只读写结构，POSCAR 按元素分组，公开的导出原子映射用于 MOL。目标是把结果关联到明确的计算来源、结构和帧，为各类显示提供一致的输入。见[格式 API](../../api/formats.md#结构读写)和 [VASP 输出文件](https://vasp.at/wiki/index.php/Category%3AOutput_Files)。

## 验收条件与实施步骤

1. 定义独立于源结构的只读结果数据，记录文件来源、格式及可知的程序版本、物理量、单位、运行标识、离子步或帧及自旋通道。分别记录文件明确报告的运行终止和收敛状态，未知值保留未知。导入状态和图层显示状态分别呈现。
2. 为 POSCAR 导出保存实际文件序号与源 `AtomId` 的映射及导出结构凭据。以输出文件内的原子和晶胞数据验证绑定，在缺少可信映射时允许显式配准或作为独立结果结构打开。数量、元素、顺序和来源冲突给出可定位的诊断。
3. 为松弛后结构和逐步结果记录对应帧的晶胞与原子位置，并共享坐标换算。支持 `CONTCAR` 的几何输入，约束字段遵循 [POSCAR 导入契约](../../api/formats.md#poscar-导入)。按文件记录与结构匹配关系关联结果，歧义时由用户选择。
4. 用混合元素重排、优化后晶胞、缺少映射、来源不匹配及截断文件验证配准、诊断和状态。浏览器检查导入失败保留当前文档与图层，成功导入的结果可交给[图层](../2026-11-04-calculation-result-layers/README.md)使用。
