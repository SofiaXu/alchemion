# 10k 源编辑 CPU 分段分析

状态：未开始。需求：R-021。验证：T-PERF-01，并按实际优化影响选择 T-DOM/T-EDIT/T-RUN 场景。

## 需求与当前事实

对正式基准中相同的 10,000 源原子、20,000 键、identity-only 合法分子场景进行 CPU 分段分析。2026-10-30 整理前 Windows 工具链验收记录的最差源编辑端到端 p95 为 2.451 秒，完整源构造/载入/计算/显示最差 5.777 秒；这是待分析观察，不是已归因问题，也不混同 renderer 的局部更新预算。

基准为 `124275f` 加 Node26/pnpm12 工具链升级，本机 Arc B390/Chromium。不同工具、电源、浏览器或源码布局下的历史数字不直接用于回归归因。真实对称/邻胞由功能测试覆盖，此夹具不冒称从较小源真实扩胞。

## 验收条件与实施步骤

1. 从 `scripts/viewer-bench.mjs` 和 `tests/viewer` 记录固定源、选项、tarball 与输入散列、设备/浏览器/电源环境。
2. 分别记录源复制、结构校验、键端点查找、Worker 计算及完整帧等待耗时；保留原始时间线在 `.tmp/source-edit-performance`。
3. 得到可复现瓶颈及分段总和与端到端时段的对应，区分主线程、消息传递和渲染。
4. 基于测量结果提出后续优化与验收目标；若拟使用局部 AtomId 索引，先明确失效和事务边界，并用独立科学参考验证等价。

本任务首先完成分析，不预设瓶颈或性能改善数值，不因静态阅读直接实施未经验证的算法替换。
