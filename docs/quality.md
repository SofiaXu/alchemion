# 质量、独立参考与性能契约

本文维护稳定测试编号、验证原则、独立参考方法和性能预算。需求编号来自[产品规范](product.md)，科学容差来自[领域规范](domain.md)，当前命令与输出位置见[开发指南](development.md)。本文不保存某轮执行报告。

## 验证原则

按实际变更运行最小充分集合，新增、扩大或重复检查须有具体技术理由；不默认调用全量 `check`。普通单元和浏览器默认最多 4 进程、无自动重试，浏览器可用 `TEST_WORKERS` 调整；资源不足时根据实际观察降低并行，不人为复制单场景。GPU 基准独占串行。

科学计算以解析解、独立推导或可追溯参考数据作 oracle，不能把生产函数输出换名当预期。小规模全枚举可对照优化实现；单位、矩阵方向、周期边界、默认容差和损失策略统一引用领域规范，不在测试中另定相冲突的规则。

Node 上运行单元或声明检查不构成 SDK 的 Node 运行时承诺。Worker、异步提交、三维交互和生命周期使用真实浏览器场景；截图辅助核对可见状态，不能单独证明数值、身份映射或资源释放。分发使用仓库外安装真实 tarball 的消费者，不通过源码 alias 绕过 exports、声明或 Worker URL。

每次验证记录日期、commit 与未提交输入、工作目录、命令、工具/浏览器/硬件版本、输入或随机种子、预期/参考、退出码、实际结果和限制。明确区分“未运行”“失败”“已通过”；跳过、缺浏览器或环境不满足不算通过。结果写入忽略的 `.tmp` 或 CI artifacts，不再把会话日志、截图和压缩快照提交到 docs；长期有效规则归并正式文档，可复用输入和参考留在测试/工具目录。

纯文档变更检查链接、需求/测试编号、源码依据、命令及事实/待办一致性，不据此声称运行时通过。历史成功不代替新变更的验证；新版本工具链、其他 OS 或真实 Safari 的结论必须来自对应实际运行。

## 独立科学参考

[科学参考生成器](../scripts/scientific-reference.py)不导入 TypeScript 生产代码。参考资产为[scientific-reference.json](../packages/alchemion/src/core/__tests__/fixtures/scientific-reference.json)，保存输入、版本、结果和完备性证书。固定生成环境为 Python 3.12.10、NumPy 2.2.6、SciPy 1.15.3；[依赖文件](../scripts/scientific-data/requirements.txt)同时固定 spglib 2.6.0、periodictable 2.0.2 等数据工具，仅供开发。

六个自编胞覆盖立方、正交异长、单斜、三斜、旋转倾斜基矢和多壳反例。参数由给定基矢的长度/点积独立求出，体积、逆矩阵与坐标由 NumPy 线性代数计算，不复制生产参数到基矢的组件公式。多壳反例的基矢列为 `(1,0,0)`、`(2.2,0.5,0)`、`(0,0,1)`，可揭示固定邻居范围的不足。

超胞与配位使用新增能力的解析输入，不重生成既有 golden。配位斜胞反例基矢为 `(1,0,0)`、`(2.2,0.5,0)`、`(0,0,10)`，单源原点、半径 0.65 Å，仅 `(-2,1,0)` 与 `(2,-1,0)` 两邻居，距离 √0.29；固定相邻一层会漏检。立方配位凸包与解析四面体另核体积、面定向和大尺度可表示/溢出边界。PNG 文字像素测试使用受控中性元素配色，避免把氧原子的红色误认成测量文字。

BZ 参考使用 SciPy/Qhull Voronoi 原点胞与 ConvexHull 体积，独立于生产增量半空间裁剪。参考以倒易矩阵最小奇异值给出遗漏格矢长度下界：`σmin(B) * (shell+1)`，在下界严格大于当前最大顶点半径两倍并留数值裕量后终止；同时检查全部已枚举半空间。现有六组证书的枚举壳为 `3/3/3/3/3/6`。生产使用逆矩阵 Frobenius 范数界，不能拿生产终止判断生成参考自身的证书。

其他独立基准包括：立方 BZ 的八顶点/六面/十二三角形/体积解析解；明确坐标的距离、角和二面角；小体系独立全对成键枚举；空间群闭合与逆元的整数运算。变更科学实现时按相关输入验证，不为格式化或文档整理重生成 golden。

重生成前审查公式、输入和固定环境；生成器默认拒绝覆盖已存在参考。可用 `--output` 指向新的 `.tmp` 文件进行对照，审查差异和证书后再有意识更新测试资产，不能静默覆盖认可预期。参考不进入 SDK tarball 或运行依赖。工具的执行方式见[开发指南](development.md#独立参考与数据工具)。

## 独立格式核验

[CIF fixture 生成器](../scripts/format-cif-fixtures.ts)和[MOL/POSCAR fixture 生成器](../scripts/format-mol-fixtures.mjs)把项目自产算术真值、原输入和待核验 SDK 输出写入 `.tmp/format-reference`。预期由明确算术输入声明，不由生产 reader 或科学派生函数反向生成。当前集合覆盖 17 份输入/输出，包含 CIF1/2 非正交晶体、CIF2 Unicode/容器文本、两版 MOL 属性/立体/续行/编号、有限周期裁剪及 POSCAR 元素分组。

[独立格式核验器](../scripts/format-reference.py)使用 Python 3.12.10，依赖由[固定清单](../scripts/format-reference-requirements.txt)声明：PyCifRW 5.0.1、NumPy 2.2.6、SciPy 1.15.3、RDKit 2025.9.6、ASE 3.26.0、openbabel-wheel 3.1.1.23。Open Babel 实际运行时字符串为 3.1.0，报告须同时记录包装与运行版本。

| 工具       | 独立核验范围                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| PyCifRW    | CIF1/2 语法、block、Unicode、容器和文本。                                                                        |
| NumPy      | 从晶胞度量矩阵作 Cholesky 分解并线性求解，核基矢、体积、分数/笛卡尔、数值不确定度及 U/B 转换。                   |
| RDKit      | 原始两版 MOL 的原子/键、坐标、形式电荷、同位素、映射号、基本 parity/键立体、自由基电子数、原始续行与非连续编号。 |
| ASE        | POSCAR 基矢、Direct 坐标、元素顺序/计数与体积。                                                                  |
| Open Babel | 补充 singlet/doublet/triplet 的 spin multiplicity；RDKit 的电子数不能独自区分 singlet/triplet。                  |

Windows 读取 expected JSON 和文本均显式使用 UTF-8。Open Babel 的参考通道对 V3000 token 内物理续行存在限制：仅该 spin 核验通道按 CTfile 精确拼接物理续行，保留全部科学字段和非连续编号；RDKit 仍核验未改动原字节。报告分别记录原文件与展开传输的 SHA，不能为迎合独立工具改写生产格式或删除场景。

核验器保存工具版本、输入 SHA、逐文件观察/失败和退出码，可用 `--file` 仅复验有理由受影响的文件，`--report` 分开保存结果。独立工具只在本地开发环境运行，不上传用户文件、不进入浏览器依赖；安装成功不等同格式核验通过。

POSCAR 导入参考使用 `format-poscar-fixtures.mjs` 的自产算术输入及独立 ASE：非正交 Direct、正 Cartesian、负目标体积和三分量缩放的 Direct/Cartesian，共五组输入及对应输出。`--poscar-imports-only` 只加载这组预期，同时把 SDK 读取的基矢、分数坐标与元素直接对照 ASE；不以单纯自往返代替独立验证，也不顺带运行 CIF/MOL 参考。

## 一万实例性能口径

规模按最终派生显示实例计数。正式采集器使用真实 tarball，固定 10,000 原子/20,000 键、1920×1080、DPR 1，空间填充与球棍各三轮。当前夹具为合法 10k 源分子的 identity-only 显示，不宣称由 500 个源原子真实扩胞；周期/对称、晶格/倒易/BZ 和实例回源另由功能场景证明。

每轮独立页面先冷测准备好的渲染快照至首次完整帧，再预热 10 秒，执行固定相机轨迹 60 秒、200 次点击、100 次百原子更新和20轮创建/销毁。保存全部逐次数据、正确性探针与汇总，以六轮最差值判定。真实 GPU 更新还用 readPixels 核验，不能只测调用返回时间或相机运动。

| 指标              | 预算                             | 测量边界                                                                 |
| ----------------- | -------------------------------- | ------------------------------------------------------------------------ |
| renderer 首帧     | ≤ 5 秒                           | 准备好的渲染快照至完整帧，不含网络/文件/科学计算；完整载入另报。         |
| 持续交互          | median FPS ≥ 30                  | 连续60秒固定轨迹，另报 frame time p95、长任务。                          |
| 点击/拾取反馈     | p95 ≤ 100ms                      | 点击发出至正确源 ID/选择可观察，包含拾取与事件。                         |
| renderer 局部更新 | p95 ≤ 100ms                      | 百原子变更对应派生快照准备后至完整显示；源编辑→重算→显示另报。           |
| 20轮创建/销毁     | 自有资源归零且不累积             | GPU、Worker、RAF、监听/观察器；有界引擎缓存解释归属，JS heap只报告趋势。 |
| 产物体积          | 记录 raw/gzip 与引擎/Worker 分项 | 使用实际安装包及最小消费者，不凭空设 KB 上限，不把 gzip 当运行内存。     |

报告记录硬件/GPU/驱动、OS、浏览器完整版本、电源模式、是否软件渲染、tarball SHA 及采样前后源码输入散列。软件渲染只证明功能；实测单设备不外推所有硬件，Playwright WebKit 不等于真实 Safari。未满足预算如实报告并定位，不缩小数据量、放宽指标或拿其他环境结果替换。

`--mode/--round` 用于有明确技术理由的子集复验；`--resume` 只续同输入/包散列的缺失轮次。子集和 `--artifacts-only` 不构成性能关卡通过，硬件不足标为未运行。浏览器、消费者、开发冒烟和基准的分名结果位置见开发指南。
