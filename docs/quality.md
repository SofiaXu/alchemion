# 质量、验证与性能契约

状态：M0 定义目标，M1 建立工程入口（2026-10-29）。历史与迁移后实际执行结果见 [M1 证据](evidence/m1-foundation.md)；科学和功能场景仍按负责阶段落实。本文件是测试场景编号与命令契约的权威来源，需求编号来自 [product.md](product.md)。

## 验证原则与证据

当前会话遵循最小充分验证：只运行变更直接相关的测试，不默认执行全套。新增、扩大或重复检查须说明技术理由。M1 的 `check:m1` 固定选取两个迁移 CIF 文件、三浏览器工程冒烟与真实 tarball，M1 CI 已验过同一范围。M2 CI 定向运行构建、受影响类型/lint、M2 三浏览器正确性及 tarball 冒烟，不默认重复 CIF 或全部业务测试。浏览器进程默认 4，可通过 `TEST_WORKERS` 调到 4–8；资源不足时有证据地降低。不启用自动重试。

M4使用独立phase入口与定向CI：仅新格式、编辑、运行时及受影响模型校验；M3算法/数据未变时不触发整个科学关卡，M2亦不随M4共享脚本触发。Windows首跑后仅复验失败或因具体缺口改变的文件；Ubuntu复验本交付集合是为检查路径/换行和真实打包Worker的跨平台差异。纯文档归档只查格式/链接。历史`check:m1`的旧CIF文件已移除，当前脚本明确指向新版CIF测试目录，不作为M4默认入口。

科学计算使用解析解、独立推导或可追溯参考数据作 oracle，不能把旧函数结果换个名字当预期值。小规模参考算法可用于对照优化实现，但要验证其公式与单位。容差、晶胞矩阵方向、倒易约定、周期边界和损失策略统一引用 [领域规范](domain.md)，测试不得另定相冲突的常量。

单元测试可使用 Node 上的测试运行器，但这不构成 SDK 的 Node 运行时承诺。浏览器行为必须在真实浏览器引擎中验证；截图可以证明可见状态，不能单独证明数值、拾取映射、资源释放或 Worker 正确性。

每份验证证据记录：日期与 commit、工作目录、工具与浏览器版本、命令、输入/随机种子、oracle 或预期行为、退出码、实际结果与限制。状态只取“未运行”“失败”“已通过”；环境缺失、没有浏览器二进制和跳过用例均不能算通过。证据文件的目标位置为 `docs/evidence/`，由实际执行阶段创建，未生成前不得链接为现成报告。

## 一万实例测量口径

以下预算是 M0 制定的默认验收目标，**未经实测，不代表历史或新版实现已达到**。M2 用于候选比较；M5/M6 必须在正式集成与实际打包消费者上复验。测量报告固定硬件/显卡/驱动、OS、浏览器完整版本、电源模式及是否使用软件渲染；软件渲染结果单独标记，不充当桌面 GPU 性能结论。

- 场景固定为扩胞后的 10,000 个原子显示实例和 20,000 条键，使用可重复构造的 RenderSnapshot；空间填充和球棍均测。分辨率 1920×1080、DPR 1；禁用与场景无关的调试覆盖层。晶格/倒易/BZ 与编辑功能另有正确性用例，不能以关闭必需功能掩盖其性能退化。
- 每种显示模式各测 3 轮，候选按 A/B、B/A、A/B 顺序交替。每轮独立加载页面，先冷测首次 RenderSnapshot 的完整帧，随后预热 10 秒，再执行固定相机轨迹 60 秒。点击采样 200 次，100 原子局部更新采样 100 次，记录全部逐次延迟、各轮汇总及正确性；门槛按所有模式/轮次的最差结果验收，不能用预热后的首帧或遗漏事件冒充达标。选择引擎时按 ADR 0002 比较对应指标。

| 指标           | 目标预算                         | 边界                                                                                                              |
| -------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| renderer 首帧  | ≤ 5 秒                           | 从已准备好 RenderSnapshot 交给 renderer，到首次完整帧；不含网络、文件读取与科学计算。完整导入和计算耗时另行报告。 |
| 持续交互       | median FPS ≥ 30                  | 连续 60 秒固定交互；另报 frame time p95 和长任务，不能用瞬时 FPS 峰值验收。                                       |
| 点击/拾取反馈  | p95 ≤ 100 ms                     | 从发出点击到正确源 ID/选择状态可观察，包含拾取和事件派发。                                                        |
| 局部更新       | p95 ≤ 100 ms                     | 100 原子变更对应的派生快照准备后，到更新内容完整显示；另报编辑→科学重算→显示端到端耗时。                          |
| 20 轮创建/销毁 | 自有资源计数归零且不累积         | 包含 GPU 资源、Worker、RAF、事件/观察器。引擎公共缓存单独解释归属；JS heap 仅记录趋势，不声称精确归零。           |
| 产物体积       | 记录 raw/gzip 及引擎/Worker 分项 | 本轮不凭空规定或宣称达到 KB 上限；M2 作为选型依据，M6 在同口径下报告正式产物差异。                                |

浏览器或硬件不满足预算时，报告真实结果和瓶颈，修复后重跑受影响场景；不得自行调小原子/键数、放宽目标或用未确认的硬件结果替换既定证据。硬件可用性不足时状态为未运行或存在阻碍，正确性测试可继续推进。

| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `pnpm build`             | 按 SDK（含声明/Worker）→demo 的依赖顺序构建；无 CJS、测试、调试源码或旧兼容入口混入正式产物。                                                                                                                                       |

| `pnpm bench -- --smoke`  | M1 运行 128 原子、120 帧的真实采集冒烟；输出环境和原始帧时间，不构成 T-PERF-01 通过。固定一万实例/两模式/全部指标由 M2 补齐。                                                                                                       |

M1 可以先建立测试与性能 harness，后续场景随阶段补齐；空测试集合、仅打印成功的脚本或永久跳过不构成阶段交付。每份计划须明确当前阶段已经实现哪些场景。

M2 新增显式参数：`pnpm test:browser -- --phase=m2` 构建独立宿主并只匹配 M2 场景；无该参数仍为 M1 冒烟。`pnpm bench -- --renderer-selection` 构建单候选 ESM 消费者、验证其产物，再按 A/B、B/A、A/B 在真实硬件 GPU 上串行采样两种模式各三轮。软件渲染仅可提供功能证据。`--artifacts-only` 只检查体积与 ESM 消费者；`--skip-artifacts` 复用本轮已验证产物；`--resume` 只续跑同一输入/代码的缺失轮次；`--candidate=`、`--mode=`、`--round=` 用于明确限定重跑，不能用子集宣称完整选型。

完整双候选比较实现保留于 07527f8；当前树仅含获选 Three，上述常规 bench 在当前树复验其两种模式各三轮，不宣称仍可直接运行落选后端。

M4新增`pnpm test:browser -- --phase=m4`，构建独立宿主并只运行`@workspace`的M4场景；`pnpm test:package -- --phase=m4 --project=chromium`安装真实tarball，核对三个入口、core/formats无DOM声明、生产计算Worker、编辑/历史和受影响历史输入的最小回归。`--prepared`只用于复用同轮已构建的SDK。并行上限4，单个tarball场景实际只用1个进程，不人为复制场景。M4无canvas的运行时验证不充当M5三维或性能验收。

`--resources-only --source-ref=<commit>` 只从指定 Git 提交恢复比较资产到忽略目录，安装其精确引擎依赖，用 CDP 核对 20 轮全局监听归属，不重跑性能。软件功能验证以 `M2_FUNCTIONAL_SOFTWARE=1` 显式选择，使用同步 GPU 完成和有界任务交付，不提供帧呈现性能证据；硬件 bench 拒绝此路径。M2 Ubuntu 四进程软件验证已实际超时，改为两个进程并保留完整 10k/20k 及几何；证据与复验理由见 M2 报告。

依赖 SDK 产物的独立命令必须显式准备其前置产物；聚合检查可以通过内部任务编排复用一次构建，不能为了避免重复准备而依赖前一会话留下的 dist。SDK 自身的源类型检查不得依赖 demo，从而保持构建依赖有向无环。

## 浏览器与阶段关卡

目标是现代桌面 WebGL2。每轮浏览器证据记录 Chromium、Firefox、WebKit 的具体版本与 WebGL2 可用性；无 WebGL2 时 SDK/demo 应提供明确错误，测试须验证该路径。真实 Safari 验证仅在确有设备和版本记录时才能声称完成。

M0 验收 T-DOC-01 与来源缺口登记，不要求也不虚称运行历史代码。M1 验收工程可重复性和可运行 harness；M2 为渲染选择提供相同条件的证据；M3/M4 验收科学/格式/状态；M5 验收完整 viewer；M6 把全部已批准需求串成 demo 与打包消费者的最终证据。路线与入口见 [roadmap.md](roadmap.md)。
