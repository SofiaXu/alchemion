## 目的与可见结果

SDK 消费者能够读取/输出声明范围内的 CIF1/CIF2、MOL V2000/V3000 和周期 POSCAR，获得可定位诊断及显式损失信息；可以在无 viewer 的环境中使用结构编辑事务、undo/redo，并通过浏览器任务运行时安全执行核心派生计算。

本阶段结束时不要求 demo 界面已经完成，但格式、命令/历史和任务 API 必须能被独立消费者调用和验证。不能用 viewer 私有状态代替这些模块的正式契约。

## 实施步骤

1. **确定边界与诊断。** 按架构接口实现文本/选项到领域快照、快照/导出选项到文本的编解码边界，结果包含结构或文本及诊断。诊断保存稳定代码、error/warning/info、字段/记录/行列和格式版本；不能只抛无位置的 `Invalid format`。格式专用 AST/原文结果由格式模块管理，不污染科学核心。为严重错误和显式损失路径建立统一测试入口。
2. **实现 CIF 文档与晶体映射。** 分离 tokenizer/文档语法、字段映射与领域校验。支持产品矩阵内 CIF1/CIF2 的标量、loop、合法容器、多个 block、版本识别、缺失标记和不确定度；拒绝不完整 loop 行和标准非法构造。文档层返回全部 block；结构层一个 block 可自动选，多个 block 必须由名称/索引选择，错误返回候选。传统/dotted 同义字段归一，冲突报错；从可选标签解析元素，缺失类型列且可从标签唯一推断时给出假设诊断，不能因提前索引空列而崩溃。
3. **完成 CIF 输出与损失控制。** 晶胞与坐标使用 M3 权威转换，volume 用于一致性检查；空间群 setting 不能猜测。结构 writer 输出产品支持字段，正确引用字符串和 `.`/`?`；CIF2 值不能静默降级为 CIF1。未映射科学类别、各向异性位移或不可表达的显式键等产生逐项损失诊断，默认拒绝有科学损失的导出；显式接受损失后仍保留警告。低层文档读写可保留未知类别，但不能声称任意编辑后的文档语义无损。
4. **实现 MOL 两版本。** 按版本标识分派，解析 V2000 固定列与属性记录、V3000 atom/bond block、续行及非连续编号；校验计数、端点、元素、坐标、电荷/同位素/自由基和产品声明的键阶/立体标志。默认输出 V3000；V2000 显式选择且对 999 数量限制及其他不可表达属性报错，不自动升版。查询/反应/聚合物等超出支持范围的科学构造不能静默丢掉。周期输入仅能在显式有限快照请求下导出 MOL，快照范围与重复实例身份必须清楚，转换为 Å 笛卡尔坐标并报告周期信息损失。
5. **实现周期 POSCAR 导出。** 拒绝无晶胞、空结构、部分占位或未知占位；不创建默认盒、不替用户挑占位物种。输出缩放因子 1.0、列向量对应的三行基矢、首次出现顺序的元素及数量、`Direct` 源分数坐标。校验行数/分组/总数；标签、显式键、空间群、位移等信息无法表达时遵守显式损失接受规则。不把当前显示扩胞结果当作默认源结构导出。
6. **实现命令事务与历史。** 增删源原子、改元素/坐标、改晶胞以稳定 ID 操作；批量命令先在草稿中完整校验再提交。改变晶胞保留分数坐标，并使全部派生数据失效；实例位置编辑按逆变换回写源。失败/空操作不入历史，undo/redo 恢复 ID 和内容但 revision 递增。load 在解析/结构校验成功后提交新源、清历史和选择/测量；前置解析/校验失败保留旧状态，提交后的派生/渲染失败保留有效新源并进入 error，load Promise 拒绝且允许恢复。默认 100 个事务，可配置；同一事务不拆成数个历史项。此模块不依赖 DOM/渲染引擎，派生与显示只是事务成功后的消费者。
7. **实现浏览器任务适配。** 同步/worker 使用 M3 相同算法。每个任务携带 requestId、documentId、revision 和类别；回包只在仍匹配时提交，取消、超时、异常、worker 退出及 dispose 都必须使 Promise 完成。默认任务超时 30 秒，可配置；取消/销毁以 AbortError 结束，超时/算法错误保留明确错误类型。相同派生类别采用 latest-wins，结构命令按序执行且不能被丢弃。运行时资源归属明确，多消费者/多 viewer 不共享可变文档状态；失败可重新创建执行器，但不能无限重试或吞掉错误。
8. **独立格式核验与交付。** 扩展并校正旧 fixture，加入每项字段和损失路径的小样例。SDK 自身往返之外，使用独立工具验证 CIF、MOL 与 POSCAR；固定工具版本、保存规范引用及输出摘要，避免只验证“自己写的自己能读”。汇总证据到目标文件 `docs/evidence/m4-formats-runtime.md`，更新支持矩阵、接口文档、本计划及交接，向 M5 交付无界面依赖的稳定 API。

独立参考应在实施开始时固定具体工具版本并记录到证据：CIF 使用与本项目无代码复用的规范校验/晶体解析工具，MOL 使用独立 CTfile 解析工具，POSCAR 使用独立结构读取工具；工具须在本地运行，不把用户文件上传外部服务。若某个独立工具不支持要求中的标准字段，换用支持该字段的独立工具并保留原因，不删去该项验收来适配工具。标准来源为 [IUCr](https://www.iucr.org/what-we-do/digital-standards/cif/specification)、[BIOVIA](https://discover.3ds.com/sites/default/files/2020-08/biovia_ctfileformats_2020.pdf) 和 [VASP](https://vasp.at/wiki/POSCAR)。

M1 完成后在仓库根目录使用目标命令 `pnpm test`（单次）、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`pnpm test:browser` 和 `pnpm test:package`，先运行相关场景再执行全部必需检查。迭代时的 watch 模式为 `pnpm test:watch`，不作为完成证据。`pnpm check` 的聚合范围及 `pnpm bench` 的运行方式以质量规范为准；本轮 M0 未建立或执行这些目标命令。

关卡：产品格式矩阵逐项通过；独立解析证明输出科学语义；事务/历史不依赖 viewer；全部异步终结路径可复现，无永久 pending Promise 或旧结果污染。M5 只需组合已有能力，不再承担补写格式/历史正确性的隐含任务。

## 中断与恢复

按模块及格式小步推进，任何支持矩阵变化同步产品/领域规范。停止前记录已支持字段、仍缺字段、失败 fixture、已运行命令和证据；下次从最小失败样例或运行时竞态复现入口恢复，不根据“文件可打开”推断其他格式字段已完成。

测试生成物可以重新生成，但先核对工作区和来源，不覆盖他人样例。旧格式实现仅作为基准阅读，不在正式发布包中与新版并列维护。未达关卡的能力保持未完成；接口修订同步架构和 M5 计划，避免界面绕过正式接口。
