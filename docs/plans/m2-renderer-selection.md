# M2：渲染后端同条件验证与定案

状态：进行中（2026-10-29）。
需求：R-010、R-014、R-019、R-021、R-023。
测试：T-VIEW-01、T-VIEW-02、T-VIEW-03、T-RUN-01、T-PERF-01、T-PKG-01。

## 目的与可见结果

取得可重跑的 Three.js/Babylon.js 对照结果，接受且只接受一个正式渲染后端，为 M5 提供经过验证的实例化、拾取、更新、清理和构建方式。此阶段不实现完整 viewer 或科学算法，不将候选原型发布成双后端 SDK。

## 上下文与入口条件

- M0 文档与 M1 工程基线已经完成；M1 的 workspace、浏览器测试、构建和基准命令可用；M2 参数由本阶段新增。
- 读取 [架构](../architecture.md)、[质量规范](../quality.md)、[ADR 0001](../decisions/0001-project-foundation.md) 与 [ADR 0002](../decisions/0002-renderer-selection.md)。后者的硬门槛及有限决策规则是本阶段的选择依据。
- 可运行目标桌面 WebGL2 浏览器，能记录真实设备/GPU/驱动和浏览器版本。无可用 GPU 或只能软件模拟时，可以开发夹具，不得据此完成选型。
- M2 不依赖尚未完成的 M3/M4。使用最小引擎无关 RenderSnapshot 测试契约、已准备坐标和测试 Worker，验证传输与取消模式；正式科学推导和编辑调度由 M3/M4 实现后继续验证。
- 本轮授权明确保留历史 viewer/demo 至 M5/M6 迁移；M2 候选是开发验证资产，不改变 SDK 公开入口。定案只收束新候选，旧 Babylon 7.23.0 依赖单独登记，不视为新版第二后端。
- 固定四个工作包：主会话负责集成/脚本/配置/文档/Git；三个子代理分别完整负责 Three adapter、Babylon adapter、共享夹具/Worker/浏览器与采样资产，不再拆分。

## 实施步骤

1. **冻结比较输入。** 建立确定性夹具和共享浏览器测试页；原子放在间距 3 Å 的 25×20×20 格点并交替四种元素颜色，每个实例拥有可核验的实例/源 ID。以 x 为最快变化索引，连接所有 +x 邻点（9,600 条）与 +y 邻点（9,500 条），再按索引顺序加入前 900 条 +z 邻点边，得到恰好 20,000 条无重复显示键；固定坐标、颜色、相机轨迹、点击索引与 100 原子更新序列。保存拓扑哈希和缓冲长度。所有候选读同一份数据，不在测量区间执行解析/扩胞/成键。
2. **锁定环境与画质。** 核对候选当前官方 API，锁定精确版本和依赖；共享夹具生成同一球/圆柱顶点、法线和索引数组，两个候选使用完全相同拓扑，并固定材质模型、光照、背景、抗锯齿、透明度、相机和裁剪范围。画布 1920×1080、DPR 1。记录全部几何细分值及截图；候选不得自行降画质。记录硬件、浏览器、供电模式、WebGL renderer，其他负载及软件渲染情况。
3. **分别建立最小 adapter。** 每候选只实现初始化、空间填充/球棍显示、实例拾取、100 原子/相关键更新、clear、dispose；不引入完整编辑器或复写科学公式。分别用官方实例化机制验证 ID 映射与更新范围。共享测试代码不依赖任一引擎，不把候选类型写入正式公开 API。
4. **验证 Worker 与隔离。** 测试 Worker 发送带 requestId/documentId/revision 的同一 RenderSnapshot；人为延迟旧修订和上一文档响应，依次测试新 load、clear、dispose 后旧消息到达。结果不得覆盖当前文档/修订，相关 Promise 必须结束。建立两个 viewer 原型实例，交替更新/销毁，确认另一实例继续正常工作。此处是接口可行性验证，不能宣称 M4 正式协议已完成。
5. **执行固定采样。** 由 `pnpm bench` 提供 renderer-selection 基准入口与参数，精确命令记录到报告；用 `pnpm test:browser` 执行正确性/生命周期场景。每候选的空间填充、球棍模式在同机各运行三轮，按 A/B、B/A、A/B 顺序，每轮独立加载页面，先测首次 RenderSnapshot 的完整帧，不提前用同一场景预热掩盖首帧开销；随后预热 10 秒，再运行固定 60 秒相机交互轨迹。执行 200 次已知实例点击（空间填充为原子；球棍各 100 次原子/键）及 100 次“每次 100 个原子”更新，记录逐次延迟和正确性；执行 20 轮创建/显示/销毁并记录资源计数。测试夹具预设可见目标避免把点中空白当引擎误差，点击使用真实指针路径并验证期望实例/源 ID。所有模式/轮次都须通过硬门槛，选择延迟取其最差值。
6. **度量产物。** 用相同 ESM 构建、tree shaking、minify 和压缩条件构建两个最小 viewer 消费者；`pnpm build` 与 `pnpm test:package` 验证无私有路径或构建器源码依赖。记录包含候选引擎的原始/minified/gzip 字节、共享内容归属、引擎专属代码清单与有效行数。不要把未加载的 lazy chunk 从总成本中隐藏。
7. **应用决策规则并收束。** 按 ADR 0002 的硬门槛、延迟、体积及平手规则作有限选择；可维护性说明与代码量作为解释证据，不参与 LOC 排分；禁止私有 API、引擎补丁与全局状态修改。候选失败只允许一轮针对性修复后完整重跑。定案后只保留获选正式依赖和实现，更新 ADR、架构及 M5 的引擎专属步骤；比较报告保留可复核的输入/版本/代码统计及失败原因。

## 验证与完成条件

| 检查           | 输入与应观察结果                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 等价显示／拾取 | 同一 10k 原子、20k 键、拓扑和画质；空间填充/球棍正确；实例 ID 与源 ID 一致，拾取不能只返回源几何 ID。                                       |
| 性能           | 两种模式各三轮，每轮首次完整帧 ≤5s，60s 交互 median FPS ≥30，200 次点击 p95 ≤100ms，100 次批量更新 p95 ≤100ms。时钟边界以 quality.md 为准。 |
| 生命周期       | 20 轮销毁后自有 GPU/Worker/RAF/观察器及监听计数归零且无累积；旧任务不重建资源。JS heap 趋势另记，不要求精确归零。                           |
| Worker／多实例 | 传输结果和直接输入一致；延迟/取消/clear/dispose 场景无过期提交；一个实例销毁不影响另一个实例。                                              |
| 分发           | 普通 ESM 消费者加载构建产物；记录完整 viewer 体积及候选专属代码量，构建消费者无需理解 SDK 内部 Worker 查询语法。                            |

使用目标命令 `pnpm test:browser`、`pnpm bench`、`pnpm build`、`pnpm test:package`，并按实际新增脚本记录参数和工作目录。报告目标位置 `docs/evidence/m2-renderer-selection.md`，原始数据与截图放在其同名资源目录；目前这些报告/资源尚未生成。报告包含两种模式各三轮数据、失败和修复、设备版本、画质、选择公式与最终理由。

**关卡**：获选候选满足全部硬门槛；ADR 0002 改为 Accepted；架构/M5 与单后端依赖一致；失败候选没有残留正式路径；验证可以由新会话按报告重跑。没有这些证据不得启动 M5；M3 可按路线图在其自身条件满足时开展。

## 中断与恢复

每轮结果记录 run ID、候选版本、夹具哈希、浏览器和设备；输入或画质变更使受影响的两组旧结果失效，不可拼接成同条件结论。中断后先检查工作区与已记录结果，保留其他代理文件，仅重跑缺失/无效轮次。

候选崩溃或资源泄漏时保存最小复现、错误和计数，清理该测试页及其自有资源后重跑，不清理他人浏览器会话。缺少目标硬件时保持未完成并记录缺项。两候选经允许修复后均失败时停止定案，按 ADR 0002 记录阻碍与可选调整；不能以降低图形质量、删除键或缩小原子数量掩盖失败。
